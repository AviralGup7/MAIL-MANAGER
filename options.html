BITS Mail Manager

Version 2 — implicit-flow auth, no client secret.

Security notice, carried over from version 1 Version 1 hard-coded a Google OAuth client secret in lib/auth.js in a public repository. That secret is in git history and must be treated as compromised. Rotate it at console.cloud.google.com/apis/credentials. This version never uses a secret at all — it uses the OAuth implicit flow, which has no token-exchange step and therefore no place a secret could be required.
Google OAuth client ID

A client ID is not a secret — it is sent in every authorization URL by design. Only the secret was ever confidential, and this build does not use one.

Appearance

Compact also hides the preview line, so every remaining character stays at full size. Shrinking the type would make the list harder to read at exactly the moment you asked to fit more on screen.

Backup

Everything you have taught this extension — rules, corrections, saved views, templates, follow-ups, your courses — lives in this browser profile and nowhere else. One reinstall and it is gone.

Sending

How long a sent message waits before it actually goes, so you can take it back. Set to 0 to send immediately. Nothing is lost either way — a message that fails to send waits in the Outbox and retries.

Reading

A reply and the message it answers share one row, the way Gmail does. Turn this off for a flat list in strict date order. Search always shows individual messages either way, so a match is never hidden behind a newer reply.

Unread is the one bit of triage you cannot reconstruct, so a mis-click should not consume it. Arrowing past a message inside this window leaves it unread. Set to 0 for Gmail's behaviour.

A delta check is one small request, not a reload. Set to 0 to only ever fetch when you press r.

Remote images tell the sender when and where you read their mail. Blocking by default is stronger than Gmail, which proxies them but still confirms the read. Choosing “always from this sender” in the reader adds an exception.

Composing

Added when you open a new message, above any quoted text — so you can see it, edit it, or delete it before sending. Separated with the standard -- marker that mail clients use to detect a signature.

Setting up your own client ID
  1. Open console.cloud.google.com and create (or pick) a project.
  2. Enable the Gmail API.
  3. OAuth consent screen → External → add your BITS address as a test user.
  4. Credentials → Create credentials → OAuth client ID → application type Web application. Yes, “Web application”, even though this is an extension. Google’s “Chrome Extension” client type only supports getAuthToken, which is Chrome-only and does not work in Brave.
  5. Under Authorized redirect URIs, add this exactly — trailing slash included:
    loading… Derived from the extension ID (loading…), which is fixed by the "key" field in the manifest and never changes between reloads.
  6. OAuth consent screen → Test users → add your BITS address, or Google refuses consent before anything else happens.
  7. Copy the client ID into the box above. Ignore the client secret — this build never sends one, which is why it uses the implicit flow rather than an authorization-code exchange.

Scope requested: gmail.modify only. Version 1 asked for six scopes including gmail.send; this build cannot send mail, so it does not ask.
