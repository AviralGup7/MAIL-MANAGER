Version 2 — PKCE auth, no client secret.

Security notice, carried over from version 1 Version 1 hard-coded a Google OAuth client secret in lib/auth.js in a public repository. That secret is in git history and must be treated as compromised. Rotate it at console.cloud.google.com/apis/credentials. This version never uses a secret at all — it uses PKCE (RFC 7636), which is the correct flow for a public client like a browser extension.
Google OAuth client ID

A client ID is not a secret — it is sent in every authorization URL by design. Only the secret was ever confidential, and this build does not use one.

Setting up your own client ID
  1. Open console.cloud.google.com and create (or pick) a project.
  2. Enable the Gmail API.
  3. OAuth consent screen → External → add your BITS address as a test user.
  4. Credentials → Create credentials → OAuth client ID → Web application.
  5. Add this redirect URI exactly:
    loading…
  6. Extension ID: loading…
    Fixed by the "key" field in the manifest, so it never changes between reloads and the redirect URI above stays valid.
  7. Copy the client ID into the box above. Ignore the secret — you do not need it.
